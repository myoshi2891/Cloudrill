## 1. シナリオと観点

利用者が、模試を選んで開始し、最後まで解いて提出し、結果と解説を確認する。この一連を、実際のアプリで通す。

- **通しの完走**: 全問に解答して手動で提出する。未解答を残して提出する。
- **時間切れ**: 制限時間を過ぎたら、自動で提出する。
- **見直し**: 一覧から問題へ移動する。提出をキャンセルして解答に戻る。
- **結果の正しさ**: 画面の得点が、解答した内容と一致する。
- **本番の規模**: 55 問・120 分の本番のパックでの確認。

自動の UI テストは、起動引数(`-ui-testing`、`-fixed-now`、`-advance-on-launch`、`-content-fixture`)で時計とコンテンツを固定して実行する。

## 3. 既存のテストで覆われていない点

- **E2E-01-05**: UI テストは、得点の表示の形(「/ 55」を含む)を確認している。得点の値が解答と一致することまでは確認していない。集計の正しさは、機能テスト(FT-03-02)で確認している。
- **E2E-01-03**: UI テストは、キャンセルのあと見直し一覧(件数の表示)が残ることまでを確認している。解答の画面に戻って解答を変えられることは確認していない。
- **E2E-01-06〜09**: 対応する UI テストを、テスト名からは特定できなかった。振る舞いは機能テスト(FT-02、FT-03)で確認している。
- **E2E-01-10〜12**: 触覚、実際の時間の経過、本番のパックは、自動の UI テストでは確認できない。
- UI テストは、main への push と手動の実行でだけ動く(`app-test.yml`)。プルリクエストでは動かない。
- CLAUDE.md の記載によると、UI テストは追加時に 19 件が成功し、その後に追加した 1 件を含む全件の再実行はしていない。
