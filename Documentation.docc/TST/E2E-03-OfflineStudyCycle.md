## 1. シナリオと観点

- **オフラインでの全機能(AC-04)**: ネットワークがない状態で、模試・練習・カード・ドキュメントのすべてを使える。
- **一連の学習**: 利用者の典型的な流れを、機能をまたいで通す。
  1. 模試を受ける → 結果を見る → 間違えた問題がカードになる
  2. カードを復習する → 翌日以降に、期限が来たカードがホームに出る
  3. 弱点のドメインを分析で確認する → そのドメインを練習する → ドキュメントを読む
- **機能ごとの画面の流れ**: 各タブの入口から、最後の画面まで進めること。

自動の UI テストは、`-network offline` を付けて実行する。ただし現在、この引数は `UITestingConfiguration.offline` に解釈されるだけで、通信を止めていない(P4 までのアプリは通信しない)。P5 以降に通信を足すときは、その前にこの設定を通信の部品につなぎ、オフラインを再現できるようにする。

## 3. 既存のテストで覆われていない点

既存の UI テストは、**機能ごとの画面の流れ**(E2E-03-01〜08)を確認している。**機能をまたぐ一連の学習(E2E-03-09〜11、16。P6 では 17)を通す UI テストは見当たらない。** 結合テスト(IT-04-15〜17)も同じ箇所が空いているので、どちらかのレベルで確認する必要がある。

- **E2E-03-09、10**: 模試の結果が、カードと分析に伝わること。利用者にとっての中心の流れである。
- **E2E-03-12**: 報告のシートの UI テストを、テスト名からは特定できなかった。振る舞いは機能テスト(FT-08-11〜17)で確認している。
- **E2E-03-13〜15**: 実機の機内モード、ブラウザ、共有の画面は、自動の UI テストでは確認しにくい。
- **E2E-03-16**: UI テストの時計は起動時に決まる(`-fixed-now`、`-advance-on-launch`)。日を進めるには、起動し直す必要がある。
