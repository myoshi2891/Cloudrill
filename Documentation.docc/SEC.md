## 1. 目的

セキュリティとプライバシーの要件は、RDD(NFR-09、NFR-10、LG-06)、BDD 8.2・8.3、DDD-P2 3.3、DDD-P5 に分かれて書かれている。この文書群は、それらを「何を・いつ・どうやって確認するか」の形にまとめたものである。

2026-11-17 時点でわかっている観点を対象にする。設計や実装が変わったら、該当する確認項目書を更新する。

## 2. 守るもの

| 資産 | 内容 | 主な確認項目書 |
|---|---|---|
| コンテンツの正しさ | 問題・解説・カードが、制作者の署名したものと一致していること | SEC-01、SEC-02、SEC-05 |
| 署名鍵 | 本番の秘密鍵が漏れないこと。テスト用の鍵が本番で通用しないこと | SEC-02、SEC-03、SEC-08、SEC-09 |
| 学習データ | 解答履歴・カードの状態・設定が、端末と利用者の iCloud の外に出ないこと | SEC-04、SEC-10、SEC-12 |
| 誤り報告 | 自由記述に含まれうる個人情報が、必要以上に保存・複製・記録されないこと | SEC-07、SEC-10 |
| 配信基盤と CI | 配信用バケット、Secret Manager、ワークフローの権限が最小であること | SEC-08、SEC-09 |
| ストアでの表示 | プライバシー表示と実際のデータの扱いが一致していること | SEC-11 |

## 4. 書式と凡例

確認項目書はすべて同じ構成にする。

1. 守るものと想定する脅威
2. 確認項目(表)
3. 事前調査で把握した現状
4. 未決事項

**確認項目の ID** は `SEC-<確認項目書の番号>-<連番>`。

**時期**

| 値 | 意味 |
|---|---|
| 現在 | 今のコードとリポジトリで確認できる |
| P5 | 配信・誤り報告(DDD-P5)の実装時に確認する |
| P6 | 拡張機能(DDD-P6)の実装時に確認する |
| リリース前 | App Store への申請前、または本番環境の構築時に確認する |

**結果**

| 値 | 意味 |
|---|---|
| 未確認 | まだ確認していない |
| 適合 | 確認方法のとおりに確認し、問題がなかった(確認日と確認者を併記する) |
| 不適合 | 問題があった(対応する Issue・PR を併記する) |
| 対象外 | 前提が変わり、確認が不要になった(理由を併記する) |

**「事前調査で把握した現状」** は、この文書の作成時(2026-11-17)にコードを読んで得た事実である。確認方法のとおりに確認した結果ではないので、「結果」には反映していない。

## 5. 要件との対応

| 要件・設計 | 内容 | 確認項目 |
|---|---|---|
| NFR-09 | 学習データは端末と iCloud にだけ保存する。サーバーには誤り報告と匿名の利用統計だけを送る | SEC-04-01〜10、SEC-06-01、SEC-07-01〜05、SEC-10-01〜04、SEC-12-01〜04 |
| NFR-10 | コンテンツパックの改ざんを検知する | SEC-01-01〜12、SEC-02-01〜09 |
| LG-06 | プライバシーポリシーとストアのプライバシー表示を、実際のデータの扱いと一致させる | SEC-11-01〜09 |
| AC-05 | 改ざんしたパックを拒否する | SEC-01-02、SEC-01-11、SEC-08-10 |
| BDD 8.2 改ざん検知 | 署名の検証とファイルごとの SHA-256 | SEC-01-01〜05 |
| BDD 8.2 通信 | HTTPS だけ。ATS の例外を設けない | SEC-06-01〜04 |
| BDD 8.2 学習データ | Data Protection と CloudKit のプライベート DB | SEC-04-01〜03、SEC-12-01 |
| BDD 8.2 API の悪用対策 | App Attest とレート制限 | SEC-07-06〜09 |
| BDD 8.2 秘密情報 | アプリに秘密鍵や API キーを埋め込まない | SEC-02-05、SEC-09-08〜10 |
| BDD 8.3 収集するデータ | 誤り報告と匿名の利用統計だけ | SEC-07-03、SEC-11-01、SEC-11-06 |
| BDD 8.3 トラッキング | 行わない | SEC-11-05 |
| BDD 8.3 データの削除 | CloudKit 上のデータも含めて削除できる | SEC-04-08、SEC-04-09、SEC-12-03 |
| BDD 7.2 誤り報告 | 個人情報の置き換え、180 日での削除、閲覧者の限定 | SEC-07-11〜13 |
| DDD-P5 5 章 | 署名鍵がリポジトリにもログにもない。`comment` をログに出さない | SEC-09-08、SEC-09-11、SEC-10-05 |

## 6. 運用

- 確認したら、該当する行の「結果」を更新し、確認日と確認者を書く。
- 「時期」が P5・P6 の項目は、対応するステップの完了条件と合わせて確認する。
- リリース判定の前に、「現在」と「リリース前」の全項目が「適合」または「対象外」になっていることを確認する。
- 新しい観点が見つかったら、既存の確認項目書に項目を足すか、番号を続けて確認項目書を追加する。
